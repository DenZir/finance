# Деньги — учёт финансов

Доходы, комиссии платёжек, кошельки, выводы и доля партнёра. Отдельно от
tg-analytics: своя база, свой вход, доступ только у владельца.

## Что есть

- **Кошельки** в своей валюте (₽, USDT, TON, TRX…): Platega (14 % с приёма),
  CryptoBot (3 %), свои крипто-кошельки. Остаток — сумма операций, в рублях — по
  текущему курсу (CoinGecko, курс можно вписать руками).
- **Операции:**
  - *доход* — сколько заплатил покупатель; на кошелёк ложится за вычетом
    комиссии, в отчёте — полная сумма и комиссия отдельно;
  - *расход* — с видом и проектом;
  - *перевод / вывод / обмен* — сколько ушло и сколько пришло; разница в рублях
    — комиссия вывода (3 %, Rapira, курс), ставки знать не нужно;
  - *выплата партнёру* — закрывает долг по проекту.
- **Проекты и виды.** VPN — пополам с партнёром: «Должен партнёру» = 50 % дохода
  за вычетом комиссий − 50 % расходов − выплаченное.
- **Главный экран:** на платёжках, на кошельках, долг партнёру, чистыми за месяц,
  «Нам должны» и «Мы должны» по рекламе; сделки рекламы, которые ждут решения;
  итоги месяца по видам доходов и расходов; список операций.

Месяц считается по Москве.

## Начальные остатки и сверка

Операция **«Остаток»** — сколько на кошельке на самом деле на дату (по кабинету
платёжки или кошелька). Разница с насчитанным ложится поправкой, которая не
доход и не расход. Так вносятся начальные остатки и делается сверка. Хранится
сам остаток: если импорт позже допишет оплаты задним числом, остаток на эту дату
останется тем, что вписан.

## Импорт оплат привата

Раз в 5 минут «Деньги» забирают оплаты из ботприватa (`GET /finance/orders`):
доход вида «Приватка», проект «Приватка MARIN», на кошелёк своей платёжки, с её
комиссией (Platega 14 %, CryptoBot 3 %). Оплата CryptoBot ложится на кошелёк в
USDT по текущему курсу, выручка в отчёте — ровно цена заказа. Тестовые оплаты и
ручные выдачи не импортируются. Повторно одна оплата не запишется.

Включение:
1. В `.env` ботприватa — `FINANCE_API_KEY=` (сгенерировать `openssl rand -hex 32`),
   затем `docker compose up -d` там.
2. В `.env` «Денег»:
   ```
   BOTPRIVAT_URL=http://127.0.0.1:30003
   BOTPRIVAT_KEY=<тот же ключ>
   IMPORT_SINCE=2026-10-01
   ```
   затем `docker compose up -d`.
3. На дату `IMPORT_SINCE` внесите «Остаток» каждого кошелька — с неё учёт
   считается полным.

## Реклама из tg-analytics

Раз в 5 минут «Деньги» забирают закупы и продажи из tg-analytics
(`GET /api/ads/finance`) — с датой от `IMPORT_SINCE`, вместе с суммой. Оплачена
ли сделка, аналитика не знает; это отмечается здесь, в блоке «Реклама»:

- **«Оплачено»** — кошелёк (по умолчанию CryptoBot; Platega в списке нет), дата
  и сколько пришло или ушло в валюте кошелька — сумма сделки подставлена по
  курсу. Продажа становится доходом «Реклама — посты» или «Реклама — сторисы»,
  закуп — расходом «Закуп рекламы», проект «Реклама». Комиссии нет. При взаимозачёте с тем же человеком: закуп —
  «Бартер», продажа — «Оплачено» на разницу.
- **«Ждём оплату»** (у закупа — «Надо оплатить») — за сделку должны заплатить,
  но ещё не заплатили. Только такие сделки — в «Нам должны» (продажи) и «Мы
  должны» (закупы), с отметкой, сколько дней прошло с выхода. Когда заплатят —
  «Оплачено» с датой прихода денег.
- **«Бартер»** — денег не было, в выручку и остатки не идёт. «Вернуть» снимает
  отметку.

Сделки без отметки — «Не разобраны»: в долги они не входят. Удалили операцию
оплаты — сделка снова ждёт оплату. Сделки без суммы (CPM ждёт просмотров, ПДП —
подсчёта) в долги не входят, пока сумма не появится. Отменённые и удалённые в
аналитике перестают ждать.

Включение:
1. В `.env` tg-analytics — `FINANCE_KEY=` (`openssl rand -hex 32`), затем
   `docker compose up -d` там (`restart` новый ключ не подхватит).
2. В `.env` «Денег»:
   ```
   ANALYTICS_URL=http://127.0.0.1:3000
   ANALYTICS_KEY=<тот же ключ>
   ```
   (порт — `PORT` из `.env` tg-analytics), затем `docker compose up -d`.

## Установка на сервер

1. Бот для входа: создайте в @BotFather, затем `/setdomain` → `dengi.routaterm.icu`.
2. DNS: `dengi.routaterm.icu` → сервер.
3. Caddy (`/etc/caddy/Caddyfile`), затем `systemctl reload caddy`:
   ```
   dengi.routaterm.icu {
       reverse_proxy 127.0.0.1:30010
   }
   ```
4. В папке проекта:
   ```
   cp .env.example .env    # заполнить BOT_TOKEN, BOT_USERNAME, OWNER_TG_IDS
   docker compose up -d --build
   ```
   `.env` читается при создании контейнера: после правки — снова
   `docker compose up -d`, `restart` его не перечитает.
