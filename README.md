# Деньги — учёт финансов

Доходы, комиссии платёжек, кошельки, выводы и доля партнёра. Отдельно от
tg-analytics: своя база, свой вход, доступ только у владельца.

## Что есть

- **Кошельки** в своей валюте (₽, USDT, TON, TRX…): Platega (14 % с приёма),
  CryptoBot (3 %), свои крипто-кошельки. Остаток — сумма операций, в рублях — по
  текущему курсу (CoinGecko, курс можно вписать руками).
- **Операции:**
  - *доход* — сколько заплатил покупатель; на кошелёк ложится за вычетом
    комиссии, в отчёте — полная сумма и комиссия отдельно;
  - *расход* — с видом и проектом;
  - *перевод / вывод / обмен* — сколько ушло и сколько пришло; разница в рублях
    — комиссия вывода (3 %, Rapira, курс), ставки знать не нужно;
  - *выплата партнёру* — закрывает долг по проекту.
- **Проекты и виды.** VPN — пополам с партнёром: «Должен партнёру» = 50 % дохода
  за вычетом комиссий − 50 % расходов − выплаченное.
- **Главный экран:** на платёжках, на кошельках, долг партнёру, чистыми за месяц,
  «Нам должны» и «Мы должны» по рекламе; сделки рекламы, которые ждут решения;
  итоги месяца по видам доходов и расходов; список операций. Переключатель
  «Месяц | Год» у итогов показывает год: строка на каждый месяц (нажать —
  открыть месяц), итог года и разбивку года по видам.
- **Бот** — запись операции одной строкой («сервер 20 usdt»), остатки, долги по
  рекламе и напоминание о них раз в день.

Месяц считается по Москве.

## Начальные остатки и сверка

Операция **«Остаток»** — сколько на кошельке на самом деле на дату (по кабинету
платёжки или кошелька). Разница с насчитанным ложится поправкой, которая не
доход и не расход. Так вносятся начальные остатки и делается сверка. Хранится
сам остаток: если импорт позже допишет оплаты задним числом, остаток на эту дату
останется тем, что вписан.

## Импорт оплат привата

Раз в 5 минут «Деньги» забирают оплаты из ботприватa (`GET /finance/orders`):
доход вида «Приватка», проект «Приватка MARIN», на кошелёк своей платёжки, с её
комиссией (Platega 14 %, CryptoBot 3 %). Оплата CryptoBot ложится на кошелёк в
USDT по текущему курсу, выручка в отчёте — ровно цена заказа. Тестовые оплаты и
ручные выдачи не импортируются. Повторно одна оплата не запишется.

Включение:
1. В `.env` ботприватa — `FINANCE_API_KEY=` (сгенерировать `openssl rand -hex 32`),
   затем `docker compose up -d` там.
2. В `.env` «Денег»:
   ```
   BOTPRIVAT_URL=http://127.0.0.1:30003
   BOTPRIVAT_KEY=<тот же ключ>
   IMPORT_SINCE=2026-10-01
   ```
   затем `docker compose up -d`.
3. На дату `IMPORT_SINCE` внесите «Остаток» каждого кошелька — с неё учёт
   считается полным.

## Реклама из tg-analytics

Раз в 5 минут «Деньги» забирают закупы и продажи из tg-analytics
(`GET /api/ads/finance`) — с датой от `IMPORT_SINCE`, вместе с суммой. Оплачена
ли сделка, аналитика не знает; это отмечается здесь, в блоке «Реклама»:

- **«Оплачено»** — кошелёк (по умолчанию CryptoBot; Platega в списке нет), дата
  и сколько пришло или ушло в валюте кошелька — сумма сделки подставлена по
  курсу. Продажа становится доходом «Реклама — посты» или «Реклама — сторисы»,
  закуп — расходом «Закуп рекламы», проект «Реклама». Комиссии нет. При взаимозачёте с тем же человеком: закуп —
  «Бартер», продажа — «Оплачено» на разницу.
- **«Ждём оплату»** (у закупа — «Надо оплатить») — за сделку должны заплатить,
  но ещё не заплатили. Только такие сделки — в «Нам должны» (продажи) и «Мы
  должны» (закупы), с отметкой, сколько дней прошло с выхода. Когда заплатят —
  «Оплачено» с датой прихода денег.
- **«Бартер»** — денег не было, в выручку и остатки не идёт. «Вернуть» снимает
  отметку.

Сделки без отметки — «Не разобраны»: в долги они не входят. Удалили операцию
оплаты — сделка снова ждёт оплату. Сделки без суммы (CPM ждёт просмотров, ПДП —
подсчёта) в долги не входят, пока сумма не появится. Отменённые и удалённые в
аналитике перестают ждать.

Чтобы не разбирать сделки по одной, отметьте их галочками (или «выбрать все» у
группы) и нажмите внизу «Ждём оплату», «Бартер» или «Не разобрана»; оплаченные
при этом не трогаются.

Включение:
1. В `.env` tg-analytics — `FINANCE_KEY=` (`openssl rand -hex 32`), затем
   `docker compose up -d` там (`restart` новый ключ не подхватит).
2. В `.env` «Денег»:
   ```
   ANALYTICS_URL=http://127.0.0.1:3000
   ANALYTICS_KEY=<тот же ключ>
   ```
   (порт — `PORT` из `.env` tg-analytics), затем `docker compose up -d`.

## Оплаты VPN

У VPN свои кабинеты: **Platega VPN** (8 %) и **CryptoBot VPN** (3 %) — заведены
сами, в кабинеты привата VPN-деньги не попадают. Раз в 5 минут «Деньги» забирают
оплаты VPN-бота из tg-analytics (`GET /api/finance/payments`, тот же ключ, что у
рекламы) — с даты `IMPORT_SINCE`. Каждая становится доходом «VPN» проекта VPN на
кошелёк своей платёжки с её комиссией; половина дохода за вычетом комиссий идёт
в «Должен партнёру».

Через какую платёжку пришла оплата, VPN-бот сообщает полем `provider`
(`platega` / `cryptobot`, см. `VPN_GUIDE.md` в tg-analytics — это дописывает
партнёр). Оплаты без него — старые и до доработки бота — ждут в блоке
**«VPN — разобрать»**: выберите Platega или CryptoBot (по одной или галочками
пачкой), «×» / «Не учитывать» — оплата в доход не пойдёт (тестовая и т. п.).
Удалили операцию оплаты VPN — следующая сверка запишет её снова на ту же
платёжку.

Включение: в `.env` «Денег» — `VPN_PROJECT=` имя проекта VPN в аналитике (как на
её экране «Проекты»), нужны `ANALYTICS_URL` и `ANALYTICS_KEY`. Затем
`docker compose up -d`. На дату `IMPORT_SINCE` внесите «Остаток» кошельков VPN.

## Бот

Тот же бот, через который входят на страницу (`BOT_TOKEN`). Отвечает только
владельцу (`OWNER_TG_IDS`) и только в личке, остальным — молчит. **Один раз
нажмите в нём /start**: бот не может написать первым, и без этого напоминания не
дойдут.

**Запись строкой.** Пришлите расход или доход — бот соберёт черновик:

```
сервер 20 usdt
20$ хостинг
хостинг 1 500 ₽
+1500 сторис
доход 300 приватка
20,5 ton
```

- Расход — по умолчанию; доход — с «+» в начале или со словом «доход»,
  «пришло», «получил». Доход из бота — без комиссии: это перевод на кошелёк, а не
  приём платёжки.
- Валюта: ₽ (р, руб, rub), $ (usdt, usd, долл), ton, trx, btc, eth; не указана —
  рубли. Кошелёк — первый в этой валюте, USDT и рубли без кошелька — CryptoBot
  (кабинеты VPN сами не выбираются, только кнопкой «Кошелёк»). Валюты суммы и
  кошелька разные — пересчёт по текущему курсу: «+1500 сторис» — «1 500 ₽ ≈
  18,29 USDT» на CryptoBot, в отчёт ляжет ровно 1 500 ₽.
- Вид и проект угадываются по словам. Расходы: сервер, хостинг, vps, vpn, домен,
  прокси — «VPN — серверы и сервисы» (VPN); подписка, сервис, claude, chatgpt —
  «Сервисы и подписки»; закуп, реклама — «Закуп рекламы» (Реклама). Доходы:
  сторис, пост, приветка или заявки, партнёрка или рефералка, приватка, vpn.
  Остальное — «Прочее».
- До записи всё правится кнопками: «Расход ⇄ Доход», «Вид», «Проект»,
  «Кошелёк», «Вчера». «✅ Записать» — операция в учёте (дата — полдень по
  Москве), под ней «Отменить» её удаляет. Черновик живёт сутки и не переживает
  перезапуск — тогда строку проще прислать заново.

**/balance** — остатки кошельков и ≈ в рублях, «на платёжках» и «на
кошельках», долг партнёру.

**/debts** — кто кому должен по рекламе: сделки «Ждём оплату», чей день уже
наступил, самые давние сверху. То же бот присылает сам раз в день, в 10:00 по
Москве, если долги есть.

Настройки в `.env` (все необязательные):

```
BOT_POLLING=on        # off — не опрашивать бота
REMINDER_HOUR=10      # час напоминания по Москве; off — без напоминаний
PUBLIC_URL=https://dengi.routaterm.icu   # кнопка «Открыть «Деньги»» под напоминанием
```

Webhook боту не нужен — сервер сам опрашивает Telegram. Бота может опрашивать
только один процесс: в журнале `[bot] опрос бота занят (409 …)` — значит, его
опрашивает кто-то ещё с тем же токеном (dev-сервер на ноутбуке) или у бота стоит
webhook (снять: `https://api.telegram.org/bot<токен>/deleteWebhook`).

## Установка на сервер

1. Бот для входа: создайте в @BotFather, затем `/setdomain` → `dengi.routaterm.icu`.
2. DNS: `dengi.routaterm.icu` → сервер.
3. Caddy (`/etc/caddy/Caddyfile`), затем `systemctl reload caddy`:
   ```
   dengi.routaterm.icu {
       reverse_proxy 127.0.0.1:30010
   }
   ```
4. В папке проекта:
   ```
   cp .env.example .env    # заполнить BOT_TOKEN, BOT_USERNAME, OWNER_TG_IDS
   docker compose up -d --build
   ```
   `.env` читается при создании контейнера: после правки — снова
   `docker compose up -d`, `restart` его не перечитает.

## Разработка

```
npm install
npm run dev        # нужен .env; на ноутбуке — BOT_POLLING=off и REMINDER_HOUR=off
npm test           # node:test, база в памяти, сеть не нужна
npm run typecheck
```
